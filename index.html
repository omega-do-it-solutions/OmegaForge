A practical guide to OmegaForge

Build your idea with an AI coding assistant.

This guide shows you what to give Codex or Claude when you want to start a project, clean up its template files, update its Forge guidance, define its interface, audit its code, or make a change. If you are an engineer, the technical section also explains how Forge keeps the work scoped, consistent with the architecture, and properly checked.

Before you begin

Have these four things ready.

They only take a few minutes to prepare and prevent most problems at the start.

  • A coding assistant on your computer

    The assistant must be able to read and change project files. A regular browser chat does not have that access.

  • VS Code ready

    Install VS Code before you begin. Your assistant will open the project folder there and continue from that folder.

  • An empty project location

    Choose a name and folder that do not already contain another project. The prepared prompt asks your assistant to check again before it starts.

  • Keep confidential information out

    Do not put passwords, API keys, access tokens, or real customer data in a prompt.

https://github.com/omega-do-it-solutions/OmegaForge

New project · Step 2 of 2

Plan and bootstrap the project

Use this after docs/product.md is complete. Send the prompt once: your assistant will pause for your review before it creates anything, then continue in the same conversation after you approve the plan.

  1. 1

    Research and recommend

    It researches suitable, current options and proposes the project structure, technology stack, interface shells, exact planned changes, and project-handoff cleanup.

  2. 2

    Review and approve

    It waits while you approve the proposal or request alterations. Any revised proposal must be shown to you before work begins.

  3. 3

    Build and show

    After approval, it creates the project, checks it, starts it, applies the approved template cleanup, and opens a working sample page for you to review.

TECHNICAL GUIDANCE USEDbootstrap-project
Continue with this OmegaForge project. Read docs/product.md, then use the bootstrap-project skill.

First, research suitable, current technology options for the documented product. Recommend the smallest appropriate project structure and technology stack. Explain the important choices in plain language and list the exact files and folders you intend to create or change.

Do not create or change the application yet. Show me the proposal and wait for my response. If I request alterations, update the proposal and wait again. Begin implementation only after I explicitly approve it.

After approval, create the runnable project baseline, install what it needs, and run the relevant checks. Then start the application and open its working sample page so I can review it. Tell me the local address and briefly report what was created and verified.

Project handoff

Remove leftover template files safely

Use this after bootstrap or before handing over an older derived project. The assistant separates disposable template material from the engineering guidance and legal files the project still needs.

TECHNICAL GUIDANCE USEDclean-template-residue
Use the clean-template-residue skill to prepare this derived OmegaForge project for handoff.

Inspect the project-facing documentation, repository metadata, GitHub templates, and redundant placeholders. Do not change anything yet. Classify each exact candidate as preserve, replace, remove, or hold for owner review.

Preserve AGENTS.md, CLAUDE.md, the built-in skills, docs/ai, product documentation, application code, configuration, and Git history. Do not delete, move, or rewrite LICENSE, NOTICE, copyright, or attribution material without my explicit direction.

Show me the TEMPLATE CLEANUP MANIFEST with the evidence, proposed action, and recovery path for every candidate, then wait for my approval.

After I approve the manifest, recheck each file and apply only the approved actions. Verify the remaining OmegaForge references, links, project identity, and foundation files. At the end, report what was removed, replaced, preserved, and held for review. Keep the answer brief and use the same language I use in our conversation.

Project health

Audit and repair the project

Use this when AI-generated code has drifted from the product or architecture, files have grown difficult to maintain, or you want an evidence-based codebase review.

TECHNICAL GUIDANCE USEDaudit-project → relevant specialists
Use the audit-project skill to audit this entire OmegaForge project and fix confirmed, behavior-preserving problems.

Read the product brief, engineering contract, architecture, interface identity, and implemented code. Inspect every application and package for product mismatch, architecture drift, mixed responsibilities, unsafe boundaries, duplicated business rules, missing verification, and frontend layouts that do not match their audience.

Treat very large files as investigation signals. When a file owns unrelated workflows, state, requests, I/O, or reasons to change, split it along the project architecture and feature ownership. Do not create arbitrary small files just to reduce a line count.

Repair only verified behavior-preserving drift. Ask before changing product behavior, public contracts, dependencies, schemas, data, deployment, or performing destructive work. Run the relevant checks after each coherent repair.

At the end, report the evidence, fixes, file splits and their boundaries, checks run, and remaining risks. Keep the answer brief and use the same language I use in our conversation.

Technical details

How does Forge guide an AI coding agent?

OmegaForge does not ship with your application or run in production. Its guidance files stay in the project repository. It also does not impose one runtime, database, application Dockerfile, Compose topology, CI provider, or host. Bootstrap derives those choices from the product brief, presents them for approval, and only then creates the project-specific foundation.

  • Rules live with the code
  • Stack and UI fit the product
  • Produces reviewable work

What happens when you request a change?

The assistant does not jump straight into editing. It defines the task, reads the relevant part of the project, changes the right code, and checks the result.

  1. Scope
    Turn the request into a defined task

    The assistant identifies the expected behavior, important constraints, and what a finished result should look like.

  2. Analysis
    Read the project before editing it

    Product documentation, engineering rules, architecture, existing code, and relevant tests are inspected first.

  3. Implementation
    Make the change in the right part of the codebase

    Forge selects one workflow and only the relevant specialist guidance so code stays with the feature or module that owns the behavior.

  4. Validation
    Check the result before handing it back

    The assistant runs the relevant tests, type checks, and build, then reports anything that remains unresolved.

Which decisions still belong to you?

Using Forge does not mean handing over every decision. Important changes remain visible and require approval where appropriate.

  • Sensitive changesDeleting files, rewriting data, and other high-impact changes are raised before they happen.
  • Code reviewThe diff, the reasons behind key decisions, and the results of checks remain available for review.
  • Releases and productionThe assistant does not deploy the project or change production infrastructure unless you explicitly ask it to.

About Omega Do and OmegaForge

Why did we build OmegaForge?

We are Omega Do, a digital team in Vienna working on design, web and app development, and AI tools. OmegaForge started with a problem we kept running into on our own projects: every time a new assistant joined the work, we had to explain the whole project again.

Meet Omega Do View the project repository

  1. Project context kept getting lost

    The product goal, engineering rules, and reasons behind earlier decisions lived in chat. When the conversation ended or changed, much of that useful context disappeared with it.

  2. One prompt is not enough for a real project

    A project needs more than generated code. It also needs a clear structure, a way to check changes, and rules for decisions that should stay with the project owner.

  3. We kept the important information beside the code

    OmegaForge stores product requirements, engineering rules, and task-specific guidance in versioned project files. That gives every new assistant a reliable place to start.

If you get stuck

Answers to common questions

If the work stops, keep the full error message and send it in the same conversation. In most cases, the assistant can continue from there.

Why is the copy button disabled?

For a new project, enter both the project name and its location. The copy button becomes available when both fields are filled in.

My assistant cannot find the requested skill. What should I do?

Ask it to confirm that it opened the root of the cloned project and read AGENTS.md. If it still cannot find the skill, the wrong folder may be open in VS Code.

The selected location already contains a project. What should I do?

Choose a different name or folder. The assistant stops on purpose because continuing could overwrite or mix with files that are already there.

Clone or update stopped with an error. What should I do?

Paste the full error into the same conversation. Ask the assistant to explain the cause before taking action and to suggest a fix that does not delete or overwrite existing files.

What if the assistant asks a technical question I cannot answer?

Say that you do not know the answer or do not want to choose yourself. Ask the assistant to recommend an option and explain the tradeoff in plain language.

Does every OmegaForge project use the same stack or Docker setup?

No. The assistant derives the stack, application Dockerfiles, Compose topology, CI, hosting, and deployment approach from that project's product requirements and presents the complete technical profile for approval. The Compose file in OmegaForge itself only provides the optional local SeaweedFS service; it is not a production topology.

What if my admin area looks like a customer dashboard?

Use the interface-direction prompt. Forge records who uses each surface and derives a suitable shell. Internal operations normally use a header and responsive collapsible sidebar, while public, customer, storefront, and checkout areas keep layouts suited to their own work.

Can Forge clean up code that an AI made too large or confusing?

Yes. Use the audit prompt. Forge inspects the implementation and can repair confirmed behavior-preserving drift. It splits oversized files by feature and responsibility, not into arbitrary line-count chunks.

Which OmegaForge files should remain after cleanup?

The cleanup keeps the engineering contract, built-in skills, and technical guidance because future assistants and Forge updates still use them. It also holds licenses, notices, and attribution until the owner explicitly decides how the derived project will handle them.
